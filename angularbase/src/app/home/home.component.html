Bevor ihr hier fortfahrt, stellt sicher, dass ihr prinzipiell alles aufgesetzt habt, um eine Angular-Anwendung zu erstellen. Weitere Infos siehe hier.

Danach gehts erstmal an die Erstellung eurer Angular-Anwendung

1. Angular-Anwendung erstellen:

1.1 Angular CLI installieren und Projekt anlegen

Falls @angular/cli noch nicht installiert ist, einmal in der windows cmd:

npm i -g @angular/cli

Dann:

ng new my-app

Bei der Einrichtung die Fragen wie folgt beantworten:

  • Styling? Scss
  • Server-Side Rendering (SSR)? Nein

1.2 Angular Material installieren

Danach noch aus dem Projektverzeichnis heraus angular material einbinden:

ng add @angular/material

Wenn nach einem Theme gefragt wird, einfach das erste auswählen. Alle weiteren Fragen können mit ja beantwortet werden.

3. Qualitygate Settings

Ansonsten diesen Eintrag manuell in die settings.json schreiben (MEIN-SONAR-PROJEKT-KEY durch euren austauschen):

Alle Regelverstöße werden nun nach jedem push in die Pipeline unter https://sonar.olb.de/ zu eurem Projekt angezeigt

3.2 Eslint und Prettier

Für einen einheitliche Code-Style und Regeln müssen neben Sonarqube auch Prettier und Eslint installiert und konfiguriert werden

Dazu folgende Schritte ausführen:

ng add @angular-eslint/schematics
npm i prettier -D
npm i prettier-eslint eslint-config-prettier eslint-plugin-prettier -D
npm i -D @olb/eslint-config @olb/prettier-config

Alle Fragen mit ja bestätigen

Nun wurde im root des Projekts eine Datei angelget: 'eslint.config.js'. Den Inhalt dieser hier anpassen (oder einfach überschreiben):

meinProjektPrefix durch den eigenen ersetzen / dieser sollte in der angular.json gesetzt werden unter dem prefix key

Damit prettier funktioniert, diesen Eintrag in die package.json mit aufnehmen (am besten direkt unter dem scripts tag)

"prettier": "@olb/prettier-config"

Zusätzlich diesen Inhalt in die .vscode/settings.json schreiben oder diese Datei mit Inhalt anlegen:

nun sollte der Quellcode nach dem Speichern automatisch formatiert werden

Wenn man möchte das der gesamte Quellcode automatisch formatiert wird, dann folgenden Befehl ausführen:

npx prettier --write .
Aber Vorsicht mit "." geht er das ganze Projekt durch

4. Angularbase installieren. In der package.json folgenden Eintrag in den dependencies ergänzen:

"@olb/angular-base": "{{ npmVersion }}",

und installieren mit

npm install

5. Angular JSON um Basis-Assets ergänzen

Dazu müssen drei Stellen in der Datei angular.json angepasst werden.

Schaut dazu im JSON unter > projects > (eure app) > architect > build und passt die folgenden drei Schritte an:

"assets": [
  ...
  {{ "{" }}
  "glob": "**/*",
    "input": "./node_modules/@olb/angular-base/assets",
    "output": "/assets/"
  }
],

"styles": [
  ...
  "@olb/angular-base/assets/styles/_themes.scss",
],

"stylePreprocessorOptions": {{ "{" }}
  "includePaths": [
    ...
    "@olb/angular-base/assets/styles/"
  ]
}

6. Modul einbinden

Für no-standalone Anwendungen

In eurem AppModule unter imports folgenden Eintrag hinzufügen:

  AngularBaseModule.forRoot({{ "{" }}
    authEnabled: true,
    authApiRootUrl: "/api",
    errorNotificationEnabled: true
  {{ "}" }})

Für standalone Anwendungen

In eurer app.config.ts die appConfig anpassen:

  export const appConfig: ApplicationConfig = {{ "{" }}
    providers: [provideZoneChangeDetection({{ "{" }} eventCoalescing: true {{ "}" }}), provideRouter(routes), AngularBaseModule.provideOlbBase({{ "{" }}
      authEnabled: true,
      authApiRootUrl: '/api',
      errorNotificationEnabled: true
    {{ "}" }}), importProvidersFrom(ApiModule.forRoot({{ "{" }} rootUrl: '/api' {{ "}" }}))]
  {{ "}" }};

Dabei authEnabled auf true setzen, falls ihr ein Backend zur Authentifizierung bereitstellt.

Dann ebenfalls unter authApiRootUrl die URL bzw. den Pfad pflegen, unter welcher HTTP-Requests gemäß eurer nginx.conf an das Backend geroutet werden. Wenn ihr nicht wisst, was ihr hier eintragen müsst, lasst einfach den o.g. Standard stehen.

Um automatisch Backend http-errors über eine Notification ausgeben zu lassen, kann man die errorNotificationEnabled Eigenschaft auf true setzen

Aktuell bei 400er und 500er Codes

7. index.css einbinden

In eurer index.html folgende Zeilen ENTFERNEN:

  {{ "<" }}link rel="preconnect" href="https://fonts.gstatic.com">
  {{ "<" }}link href="https://fonts.googleapis.com/css2?family=Roboto:wght@300;400;500&display=swap" rel="stylesheet">
  {{ "<" }}link href="https://fonts.googleapis.com/icon?family=Material+Icons" rel="stylesheet">

Stattdessen folgene Zeile an der gleichen Stelle HINZUFÜGEN:

  {{ "<" }}link rel="stylesheet" type="text/css" href="/assets/index.css">

8. tsconfig anpassen

In eurer tsconfig.json fügt ihr folgende Zeile hinzu (benötigt für moment = Datumsobjekte):

  "allowSyntheticDefaultImports": true,

9. Proxy konfigurieren

Wenn ihr ein Backend for Frontend nutzt, dann wollt ihr noch einen Proxy konfigurieren, sodass euer Frontend ohne den Zugriff auf eine andere Domain auch lokal mit eurem Backend sprechen kann. Dazu gibt es einen fertigen Proxy für die lokale Entwicklung von Angular.

Legt die Datei proxy.conf.json mit folgendem Inhalt an:

{{ "{" }}
  "/api": {{ "{" }}
  "target": "http://localhost:8080",
    "secure": false,
    "ws": true,
    "pathRewrite": {{ "{" }}
  "^/api": ""
    }
  },
  "/oauth2": {{ "{" }}
  "target": "http://localhost:8080",
    "secure": false,
    "ws": true
  }
}

Danach tauscht ihr in eurer package.json folgende Zeile aus:

  "start": "ng serve",

zu

   "start": "ng serve --proxy-config proxy.conf.json",

10. Testing mit Jasmine und Karma (optional)

Um eine Code-Coverage zu generieren und diese in Sonarqube sehen zu können:

ng generate config karma

Im root wurde nun die Datei: karma.conf.js angelegt. Den Inhalt der Datei dem folgendem anpassen oder einfach ersetzen (dabei drauf achten das der coverageReporter path stimmt)

Nun die package.json um zwei weitere scipts erweitern:

"test": "ng test --no-watch --browsers=Headless --code-coverage",
"test-local": "ng test --browsers=Standard --code-coverage"

Um "npm run test" ausführen zu können braucht ihr min. einen Test. Dieser kann auch leer sein

Als letztes noch die git ignore erweitern. Diesen Code-Block mit in die .gitignore aufnehmen:

# Reports 

  /Reports/* 

  .scannerwork/* 

  reports/* 

  coverage/*
